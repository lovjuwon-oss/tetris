# 테트리스 설계 문서

- 작성일: 2026-09-28
- 상태: 검토 대기

## 1. 개요

테트리스 가이드라인을 따르는 싱글플레이 웹 브라우저 테트리스를 만든다.

| 항목 | 결정 |
|---|---|
| 플랫폼 | 웹 브라우저 (PC) |
| 범위 | 싱글플레이 기본판 |
| 조작 | 키보드만 |
| 기술 스택 | Vite + TypeScript(strict) + Canvas 2D + Vitest, ESLint, Prettier |

### 범위에 포함

SRS 회전, 7-bag 랜덤, 홀드, 고스트 피스, 넥스트 미리보기 5개, 락 딜레이, 레벨과 점수, 일시정지, 게임오버 후 재시작.

### 범위에서 제외 (향후 단계)

효과음과 BGM, 줄 삭제 애니메이션, T-spin, 콤보, Back-to-Back, 최고점수 저장, 키 설정 변경, 추가 게임 모드, 모바일 터치, 게임패드, 멀티플레이.

## 2. 아키텍처

### 2.1 모듈 구조

```
src/
  core/            순수 로직. DOM에 의존하지 않으며 전부 테스트 대상.
    pieces.ts      블록 7종의 모양과 4가지 회전 상태
    srs.ts         SRS 벽차기 테이블, 회전 판정
    board.ts       10×40 격자(보이는 영역 20행 + 숨은 영역 20행), 충돌 검사, 줄 삭제
    rng.ts         시드를 받는 난수 생성기 (mulberry32)
    randomizer.ts  7-bag 생성기. rng를 주입받는다.
    scoring.ts     점수, 레벨, 레벨별 중력
    input.ts       DAS/ARR 상태 계산. 게임 틱 단위로 동작한다.
    game.ts        게임 상태 머신: step(state, inputEvents, dt) → state
    constants.ts   DAS, ARR, 락 딜레이 등 조정 가능한 수치
  platform/
    keyboard.ts    브라우저 키 이벤트를 논리 입력 이벤트(press/release)로 변환
    loop.ts        requestAnimationFrame 기반 고정 타임스텝 루프
  render/
    canvas.ts      보드, 고스트, 홀드, 넥스트를 그린다
    overlay.ts     준비, 일시정지, 게임오버 HTML 오버레이
  main.ts          모듈을 연결한다
```

### 2.2 데이터 흐름

1. `platform/keyboard.ts`는 키가 눌리고 떼진 사실만 기록해 논리 입력 이벤트 큐에 넣는다. 반복 이동 타이밍은 계산하지 않는다.
2. `platform/loop.ts`가 고정 타임스텝(1/60초)마다 이벤트 큐를 비워 `core/game.step`에 넘긴다.
3. `core/game.step`은 DAS/ARR, 회전, 중력, 락 딜레이, 줄 삭제, 점수를 계산해 새 상태를 반환한다.
4. `render`는 상태를 읽기만 하고 절대 수정하지 않는다.

### 2.3 원칙

- **결정성:** `core`는 시간과 입력을 인자로만 받는다. 같은 시드와 같은 입력 시퀀스에서는 항상 같은 결과가 나온다. DAS/ARR도 `core` 안에서 틱 단위로 계산하므로 재생 테스트로 조작감까지 검증할 수 있다.
- **고정 타임스텝:** 누적기(accumulator) 방식으로 모니터 주사율과 관계없이 같은 속도를 유지한다.
- **dt 상한:** 한 프레임에 반영하는 경과 시간은 최대 100ms로 제한한다. 백그라운드 탭에서 돌아올 때 계산이 폭주하는 것을 막는다.

## 3. 게임 규칙

### 3.1 블록과 생성

- 7-bag: 7종을 섞은 세트를 모두 소진하면 새 세트를 섞는다.
- 넥스트 미리보기 5개.
- 생성 위치: 보이는 영역 바로 위(21~22행)의 가운데. 폭이 홀수라 정가운데에 놓이지 않으면 왼쪽으로 붙인다.
- 생성 직후 가능하면 1칸 낙하시킨다.

### 3.2 회전

- SRS 시계, 반시계 방향.
- 벽차기 테이블은 I 블록용과 J·L·S·T·Z 공용을 따로 둔다. O 블록은 회전하지 않는다.
- 테이블의 후보 위치를 순서대로 시도하고 모두 충돌하면 회전하지 않는다.

### 3.3 이동 입력

| 항목 | 값 |
|---|---|
| DAS (자동 반복 시작 지연) | 167ms |
| ARR (자동 반복 간격) | 33ms |
| 소프트드롭 | 중력의 20배 |

- 하드드롭은 즉시 떨어져 바로 고정된다.
- 좌·우를 동시에 누르면 나중에 누른 방향이 우선한다. 나중 키를 떼면 먼저 누른 방향이 다시 적용된다.
- 모든 수치는 `core/constants.ts`에 둔다.

### 3.4 중력과 다중 칸 낙하

- 한 줄 낙하 시간(초) = (0.8 − (레벨−1) × 0.007)^(레벨−1)
- 한 틱에 여러 칸을 떨어져야 할 때는 **한 칸씩 충돌을 검사하며 반복 이동한다.** 한 번에 N칸을 건너뛰지 않는다.
- 소프트드롭 점수는 실제로 이동한 칸 수만큼만 준다.

### 3.5 락 딜레이

- 바닥이나 블록에 닿은 뒤 0.5초가 지나면 고정된다.
- 이동이나 회전에 성공하면 타이머를 초기화한다(move reset). 초기화는 최대 15회.
- 블록이 지금까지 도달한 가장 낮은 행보다 더 낮은 행에 도달하면 초기화 횟수를 다시 15회로 채운다.
- 초기화 횟수를 다 쓴 상태에서 바닥에 닿으면 즉시 고정된다.

### 3.6 홀드

- 블록 하나당 한 번만 사용할 수 있다. 새 블록이 고정되면 다시 사용할 수 있다.
- 홀드에서 꺼낸 블록은 생성 위치와 기본 회전 상태로 나온다.

### 3.7 레벨과 점수

- 1레벨에서 시작하고 10줄을 지울 때마다 1레벨 오른다. 최대 15레벨이며 이후에는 게임은 계속되고 레벨만 고정된다.

| 동작 | 점수 |
|---|---|
| 싱글 | 100 × 레벨 |
| 더블 | 300 × 레벨 |
| 트리플 | 500 × 레벨 |
| 테트리스 | 800 × 레벨 |
| 소프트드롭 | 칸당 1 |
| 하드드롭 | 칸당 2 |

- 줄 삭제 점수는 레벨업 이전의 레벨로 계산한다.
- T-spin, 콤보, Back-to-Back을 나중에 추가할 수 있도록 점수 계산은 "고정 이벤트(삭제 줄 수 등) → 점수" 형태의 함수로 분리한다.

### 3.8 게임오버

- 블록 아웃: 새 블록의 생성 위치가 이미 막혀 있다.
- 락 아웃: 블록의 모든 칸이 보이는 영역(1~20행) 위에서 고정된다.

### 3.9 상태 전이

`ready` → `playing` ⇄ `paused` → `gameover` → (Enter로 재시작) `playing`

- 창이 포커스를 잃으면(blur, visibilitychange) 자동으로 일시정지한다.
- 일시정지 중에는 게임 시간이 흐르지 않는다.
- 게임오버에서 Enter를 누르면 준비 화면 없이 새 게임이 바로 시작된다.

## 4. 화면

### 4.1 레이아웃

```
┌────────┬──────────────┬────────┐
│ HOLD   │              │ NEXT   │
│        │   보드 10×20  │ ×5     │
│ SCORE  │   (Canvas)   │        │
│ LEVEL  │              │        │
│ LINES  │              │        │
└────────┴──────────────┴────────┘
```

- 셀 크기는 창 높이에 맞춰 정수 픽셀로 정한다.
- devicePixelRatio를 반영해 고해상도 화면에서도 선명하게 그린다.
- 블록 색: I 하늘, O 노랑, T 보라, S 초록, Z 빨강, J 파랑, L 주황.
- 고스트 피스: 같은 색의 반투명 윤곽선.
- 준비, 일시정지, 게임오버 화면은 보드 위 HTML 오버레이. 게임오버에는 최종 점수와 재시작 안내를 표시한다.

### 4.2 조작 키

키 판별은 `event.code`로 한다. 한글 입력 상태에서도 동일하게 동작해야 한다.

| 동작 | 키 (`event.code`) |
|---|---|
| 좌·우 이동 | ArrowLeft, ArrowRight |
| 소프트드롭 | ArrowDown |
| 하드드롭 | Space |
| 시계 방향 회전 | ArrowUp, KeyX |
| 반시계 방향 회전 | KeyZ |
| 홀드 | KeyC |
| 일시정지 | Escape, KeyP |
| 시작·재시작 | Enter |

- Ctrl, Shift는 사용하지 않는다. Ctrl 조합은 브라우저 단축키(Ctrl+W 등)와 충돌하고, Shift 연타는 Windows 고정 키 창을 띄운다.
- 게임 중 방향키와 Space의 기본 동작(스크롤)을 막는다.
- 브라우저의 자동 반복 이벤트(`event.repeat === true`)는 무시한다.
- 창이 포커스를 잃으면 눌린 키 상태를 모두 초기화한다.

## 5. 테스트와 품질

### 5.1 단위 테스트 (Vitest)

- `pieces`, `srs`: 7종 × 4방향 모양, 벽차기 테이블 각 케이스, 벽·바닥·블록 사이 회전의 성공과 실패.
- `board`: 충돌 판정, 1~4줄 삭제, 떨어진 여러 줄의 동시 삭제, 숨은 영역 처리.
- `rng`, `randomizer`: 7개마다 모든 종류가 정확히 한 번씩 나온다. 같은 시드면 같은 순서가 나온다.
- `scoring`: 점수표, 레벨업 경계(10줄, 20줄), 중력 공식 값.
- `input`: DAS/ARR 틱 타이밍, 좌·우 동시 입력 우선순위.
- `game`: 다중 칸 낙하 중 충돌, 락 딜레이, 15회 제한과 최저 행 도달 시 재충전, 홀드 1회 제한, 블록 아웃, 락 아웃, 일시정지 중 시간 정지.
- 목표 커버리지: `core/` 90% 이상.

### 5.2 통합 테스트

- 고정 시드와 입력 시퀀스를 재생해 최종 보드와 점수를 확인한다.
- 핵심 규칙은 스냅샷이 아니라 명시적인 단언문으로 검증한다.

### 5.3 수동 확인

- 실제 브라우저에서 시작부터 게임오버, 재시작까지 플레이한다.
- 한글 입력 상태에서 조작, 탭 전환 후 복귀를 확인한다.

### 5.4 품질 기준

- TypeScript strict, ESLint, Prettier.
- `npm run check` = 타입 검사 + 린트 + 테스트. 모두 통과해야 완료로 본다.
- 작업 단위마다 git 커밋.
- 60fps 유지. 상태가 작으므로 불변 상태 반환 방식을 쓰되, 렌더링 루프에서 불필요한 할당은 피한다.

## 6. 완성 기준

- 3장의 규칙이 모두 테스트로 검증되어 있다.
- `npm run check`가 통과한다.
- 브라우저에서 시작부터 게임오버, 재시작까지 끊김 없이 플레이할 수 있다.
