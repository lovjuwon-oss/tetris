# 모바일 지원 설계 문서

- 작성일: 2026-09-29
- 상태: 검토 대기
- 기반 문서: `2026-09-28-tetris-design.md` (게임 규칙은 그 문서를 따른다)

## 1. 개요

기존 PC용 테트리스를 휴대폰 세로 화면에서도 플레이할 수 있게 한다.

| 항목 | 결정 |
|---|---|
| 방향 | 세로만 지원. 가로로 눕히면 안내를 띄우고 일시정지 |
| 조작 | 화면 버튼 + 보드 제스처(드래그 추적형) 동시 지원 |
| 구현 방식 | Pointer Events 어댑터를 `platform`에 추가. 외부 의존성 없음 |
| 게임 규칙 | 변경 없음. `src/core`는 수정하지 않는다 |
| PC | 기존 배치와 키보드 조작을 그대로 유지 |

### 범위에서 제외

가로 모드 레이아웃, 진동 피드백, 조작 설정 화면, PWA 설치·오프라인 지원.

## 2. 아키텍처

### 2.1 추가·변경 모듈

```
src/
  platform/
    gestures.ts    (신규) 순수 함수. 포인터 좌표·시각 흐름 → InputEvent 목록
    touch.ts       (신규) Pointer Events를 받아 gestures와 버튼 처리에 연결
    input-hub.ts   (신규) 키보드·터치 큐를 합쳐 drain()을 제공
  render/
    layout.ts      (신규) 순수 함수. 화면 크기 → 칸 크기 등 배치 값
    canvas.ts      (변경) layout.ts의 칸 크기를 사용
    overlay.ts     (변경) 오버레이 탭으로 시작·재개·재시작, 회전 안내
  main.ts          (변경) 입력 허브 연결, 레이아웃 전환
  style.css        (변경) 모바일 배치, 버튼, 안전 영역
index.html         (변경) 상단 바, 버튼 영역, 회전 안내 요소
```

### 2.2 데이터 흐름

1. 화면 버튼과 보드 제스처가 `touch.ts`를 거쳐 기존과 같은 `InputEvent`(press, release, focusLost)로 바뀐다.
2. `input-hub.ts`가 키보드 큐와 터치 큐를 도착 순서대로 합친다.
3. 게임 루프가 틱마다 허브를 비워 `core/game.step`에 넘긴다. 이후 흐름은 기존과 같다.

### 2.3 원칙

- **core 불변:** 터치 입력도 기존 `InputEvent`만 쓴다. 버튼을 꾹 누르면 press만 보내고 떼면 release를 보내므로, DAS/ARR은 core가 그대로 처리한다.
- **판정은 순수 함수:** 제스처 판정(`gestures.ts`)과 배치 계산(`layout.ts`)은 DOM 없이 입력과 출력만으로 테스트한다.
- **수치는 상수:** 제스처 기준값은 `gestures.ts` 상단 상수로 모아 기기 테스트 후 조정한다.

## 3. 화면 배치

### 3.1 모바일 배치 (화면 폭 700px 이하)

```
┌──────────────────────────────┐
│ SCORE 1,200  LV 3  LINES 24 ⏸│  상단 바
├──────────────────────┬───────┤
│                      │ HOLD  │
│     보드 10×20        │ NEXT  │  보드 + 오른쪽 좁은 열
│   (제스처 영역)       │ ×5    │
├──────────────────────┴───────┤
│  [홀드]  [↺]  [↻]  [하드드롭] │  버튼 두 줄
│   [ ← ]     [ ↓ ]     [ → ]  │
└──────────────────────────────┘
```

- 칸 크기 = min(⌊가능한 폭 ÷ 10⌋, ⌊가능한 높이 ÷ 20⌋), 최소 12px.
  - 가능한 폭 = 화면 폭 − 오른쪽 열 폭 − 좌우 여백
  - 가능한 높이 = 화면 높이 − 상단 바 − 버튼 영역 − 상하 안전 영역
- 오른쪽 열: HOLD 1개와 NEXT 5개를 세로로 놓고, 미리보기 칸은 보드 칸의 약 0.5배로 그린다.
- 터치 버튼은 터치 기기(`pointer: coarse`)에서만 보인다. 터치가 없는 좁은 PC 창에서는 버튼 영역을 숨기고 그 높이를 보드에 쓴다.
- 기준 화면 390×844에서 칸 약 27px, 보드 약 270×540px.

### 3.2 PC 배치 (화면 폭 700px 초과)

기존 배치를 유지한다. 칸 크기는 기존과 같이 창 높이 기준으로 계산하되, `layout.ts`를 거친다.

### 3.3 가로 방향

터치 기기에서 가로 방향(`orientation: landscape`)이면서 화면 높이가 500px 이하이면, "세로로 돌려 주세요" 안내를 화면 전체에 띄운다. 이때 `focusLost`를 보내 게임을 일시정지한다.

### 3.4 모바일 전용 처리

- 게임 영역과 버튼에 `touch-action: none`을 적용해 스크롤, 당겨서 새로고침, 두 번 탭 확대를 막는다.
- 버튼에는 텍스트 선택과 길게 누르기 메뉴가 뜨지 않게 한다(`user-select: none`, `-webkit-touch-callout: none`).
- 상단 바와 버튼 영역에 안전 영역 여백(`env(safe-area-inset-*)`)을 둔다. `index.html` viewport에 `viewport-fit=cover`를 추가한다.
- 오버레이 탭 동작:
  - 준비·게임오버 오버레이를 탭하면 `start`를 보낸다.
  - 일시정지 오버레이를 탭하면 `pause`를 보내 재개한다.
- 상단 ⏸ 버튼은 `pause`를 보낸다.

## 4. 터치 조작

### 4.1 화면 버튼

| 버튼 | Action |
|---|---|
| ← / → / ↓ | left / right / softDrop |
| 하드드롭 | hardDrop |
| ↻ / ↺ | rotateCW / rotateCCW |
| 홀드 | hold |
| ⏸ | pause |

- `pointerdown`이면 press를 보낸다. 같은 포인터의 `pointerup`, `pointercancel`, `pointerleave` 중 먼저 오는 것에 release를 한 번 보낸다.
- 버튼마다 누르고 있는 포인터를 따로 추적하므로 여러 손가락을 동시에 쓸 수 있다.
- 한 버튼이 이미 눌려 있으면 두 번째 손가락의 press는 무시한다.

### 4.2 보드 제스처

한 번에 한 포인터만 추적한다. 추적 중에 들어온 다른 포인터는 무시한다.

| 상수 | 값 | 의미 |
|---|---|---|
| `TAP_MAX_MOVE_PX` | 10 | 탭으로 볼 최대 이동 거리이자 방향을 정하는 거리 |
| `TAP_MAX_MS` | 250 | 탭으로 볼 최대 시간 |
| `SOFT_DROP_DELAY_MS` | 120 | 아래 방향이 정해진 뒤 소프트드롭을 시작하기까지의 시간 |
| `HARD_DROP_MIN_SPEED` | 1.0 px/ms | 하드드롭으로 볼 아래 방향 최소 속도 |
| `HOLD_MIN_DISTANCE_PX` | 40 | 홀드로 볼 위 방향 최소 거리 |
| `HOLD_MIN_SPEED` | 0.5 px/ms | 홀드로 볼 위 방향 최소 속도 |
| `VELOCITY_WINDOW_MS` | 80 | 속도를 계산할 최근 구간 |

판정 규칙:

1. **방향 결정:** 시작점에서 `TAP_MAX_MOVE_PX` 이상 움직인 첫 순간에 한 번만 정한다. |dx| ≥ |dy|이면 가로, 아니면 세로 모드로 고정한다.
2. **탭:** 방향이 정해지지 않은 채 `TAP_MAX_MS` 안에 떼면 `rotateCW`를 보낸다(press 후 곧바로 release). 시간을 넘기면 아무것도 보내지 않는다.
3. **가로 드래그:** 마지막으로 이동을 보낸 기준점에서 x가 한 칸 폭(렌더러의 현재 칸 크기 px) 이상 벌어질 때마다, 그 방향의 press·release 한 쌍을 보내고 기준점을 한 칸만큼 옮긴다. 방향을 바꿔 되돌아오면 반대 방향 이동이 나온다.
4. **아래 드래그:** 세로 모드이고 y가 시작점보다 아래일 때, 방향이 정해진 시점부터 `SOFT_DROP_DELAY_MS`가 지나면 `softDrop` press를 보낸다. 떼면 release를 보낸다.
5. **아래로 튕기기:** 세로 모드에서 뗄 때, 최근 `VELOCITY_WINDOW_MS` 구간의 아래 방향 속도가 `HARD_DROP_MIN_SPEED` 이상이면 `hardDrop`을 보낸다. 이미 softDrop이 눌려 있었다면 release를 먼저 보낸다.
6. **위로 튕기기:** 세로 모드에서 뗄 때, 시작점보다 `HOLD_MIN_DISTANCE_PX` 이상 위에 있고 위 방향 속도가 `HOLD_MIN_SPEED` 이상이면 `hold`를 보낸다.
7. **취소:** `pointercancel`이면 눌린 softDrop을 해제하고 나머지는 보내지 않는다.

`gestures.ts`는 시각을 인자로 받는다(`down(id, x, y, t)`, `move(id, x, y, t)`, `up(id, x, y, t)`, `cancel(id)`, `tick(t)`). 소프트드롭 지연을 판정하기 위해 게임 루프가 틱마다 `tick(t)`를 호출한다.

### 4.3 입력 합치기와 해제

- `input-hub.ts`는 여러 입력원을 등록받아 `drain()` 한 번으로 모두 비운다.
- 창이 포커스를 잃거나 탭이 숨겨지면 키보드는 기존처럼 release와 `focusLost`를 보낸다. 터치 모듈도 추적 중인 버튼과 제스처를 모두 release로 정리한다.
- 같은 동작을 키보드와 터치로 동시에 누르다가 한쪽을 떼면 그 동작은 해제된다. 동시 사용은 드문 경우라 따로 처리하지 않는다.

## 5. 테스트와 품질

### 5.1 단위 테스트 (Vitest, DOM 없음)

- `gestures.ts`:
  - 10px 미만 이동, 250ms 안에 떼면 `rotateCW`. 10px 이상 움직이거나 250ms를 넘기면 회전하지 않는다.
  - 칸 폭 30px에서 오른쪽으로 95px 드래그하면 `right` 3회. 다시 왼쪽으로 60px 되돌아오면 `left` 2회.
  - 가로 모드로 고정된 뒤 세로로 흔들어도 `softDrop`이 나오지 않는다.
  - 아래로 천천히 끌면 방향 결정 120ms 뒤 `softDrop` press, 떼면 release.
  - 아래로 빠르게 튕기면 `hardDrop`만 나오고 `softDrop`은 나오지 않는다.
  - 오래 끌다가 마지막에 빠르게 튕겨도 `hardDrop`으로 인식한다.
  - 위로 튕기면 `hold`. 거리나 속도가 기준에 못 미치면 아무것도 보내지 않는다.
  - 두 번째 포인터는 무시한다. `cancel`이면 눌린 softDrop을 해제한다.
- `layout.ts`:
  - 390×844, 360×640, 430×932 모바일에서 칸 크기가 정수이고, 보드와 오른쪽 열의 합이 화면 폭을 넘지 않는다.
  - 1920×1080 PC에서 기존 공식(창 높이 × 0.85 ÷ 20)과 같은 값이 나온다.
- `input-hub.ts`: 여러 입력원의 이벤트를 순서대로 합치고, drain 후에는 비어 있다.
- 기존 테스트는 모두 통과해야 하며 `src/core`는 수정하지 않는다.

### 5.2 수동 확인

- 헤드리스 Edge를 390×844, dpr 3으로 띄워 준비 화면을 캡처한다. 가로 스크롤이 없고 모든 요소가 보이는지 확인한다.
- 실제 휴대폰 (같은 와이파이에서 `npm run dev -- --host`로 띄운 주소로 접속):
  - 탭 회전, 드래그 이동, 소프트드롭, 튕겨서 하드드롭·홀드의 판정 느낌
  - 버튼을 꾹 누를 때 반복 이동
  - 스크롤, 당겨서 새로고침, 두 번 탭 확대가 일어나지 않는다
  - 가로로 눕히면 안내가 뜨고 일시정지된다
  - 노치와 홈 바에 요소가 가리지 않는다
  - 앱 전환 후 돌아오면 일시정지돼 있고 눌린 입력이 남지 않는다

### 5.3 품질 기준

- 기존 기준을 유지한다: TypeScript strict, ESLint, Prettier, `npm run check` 통과.
- 새 순수 모듈(`gestures.ts`, `layout.ts`, `input-hub.ts`)은 라인 커버리지 90% 이상. 커버리지 설정에 `src/platform/gestures.ts`, `src/platform/input-hub.ts`, `src/render/layout.ts`를 추가한다.

## 6. 완성 기준

- 폭 360~430px 세로 화면에서 가로 스크롤 없이 보드, HOLD, NEXT 5개, 버튼이 모두 보인다.
- 터치만으로 시작부터 게임오버, 재시작까지 할 수 있다.
- PC 배치와 키보드 조작이 이전과 똑같이 동작한다.
- `npm run check`가 통과한다.
